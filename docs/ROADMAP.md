## 2단계 결과 (Unity 연결층) — ✅ 실기에서 확인됨
Unity 6.3.22f1에서 실제로 열어 종 선택 → 유물 장착 → 노드 맵 → 전투 화면까지 클릭 확인했다.
빌드 중 잡은 문제 2건(둘 다 수정 완료, 커밋 히스토리 참고):
- `RelicEquipScreen`: 람다 안에서 void 메서드 두 개를 삼항연산자로 고르려다 CS0201 → if/else로 수정
- `UIFactory.ScrollList`: 뷰포트 이미지를 완전 투명(alpha 0)으로 만들었더니 Mask가 내용까지 통째로 가려버림
  (Unity Mask는 알파로 자르기 때문에 alpha=1 + showMaskGraphic=false로 써야 함) → 동물 선택 목록이 안 보이던 원인

- 구조: `Bootstrap.cs`(카메라·EventSystem·Canvas를 코드로 생성, 씬 파일은 완전히 비워둠) →
  `GameManager`(RunState 보유, 모든 상태 변경 메서드 제공) → `ScreenRouter`(Phase별로 화면 전체를 다시 그림) →
  `UI/Screens/*`(화면 8개: 종 선택/유물 장착/맵/전투/전투 후/이벤트/작별/결과) → `UI/UIFactory`(코드로 uGUI 조립, §2 지침).
- 한글: 레거시 `UnityEngine.UI.Text` + 나눔고딕(`Assets/Resources/Fonts`, 코드에서 `Resources.Load<Font>`). TextMeshPro는 사용하지 않음(한글 SDF 아틀라스 세팅 없이 더 단순함).
- 그래픽: 색 배경(Image)과 텍스트뿐, 스프라이트 없음(ROADMAP 상단 평가 기준 참고).
- **다음에 할 일(사람)**: Unity에서 빈 씬 하나 만들어 저장(`Assets/Scenes/Main.unity`) → 열어서 Play 버튼 → Console 확인.
  에러가 있으면 그 내용을 그대로 다음 세션에 붙여넣을 것. 특히 `FedAndFound.Game.asmdef`의 `UnityEngine.UI` 참조가
  Unity 6.3의 실제 어셈블리 이름과 다르면(EventSystem 관련 타입을 못 찾는 CS0246) asmdef 인스펙터에서 참조를 추가해야 한다.

## 3단계 결과 (전투 연출) — ✅ 실기에서 확인됨
턴 순서 바·정화 확률 표시는 2단계에서 이미 있었음. 이번엔 아래를 추가:
- `GameManager.PlayEvents`: 전투 한 턴의 이벤트를 한 줄씩 로그에 얹으며 0.22초씩 멈춤(코루틴). 재생 중엔
  `Animating=true`가 되어 `BattleScreen`이 행동 버튼을 숨기고 "…"만 보여줌(중복 입력 방지).
- `EventFeedOverlay`: 화면 전체를 다시 그려도 안 지워지는 별도 오버레이. 이벤트 종류(피격/치유/정화/기절)에
  따라 화면을 짧게 색으로 물들임(적 피격=초록, 아군 피격=빨강, 정화=파랑, 기절=진한 빨강).
- 전투 로그가 항상 최신 줄로 자동 스크롤되도록 `UIFactory.ScrollToBottom` 추가.
- **의도적으로 안 한 것**: HP바가 프레임 단위로 부드럽게 깎이는 애니메이션. Core 전투 엔진이 한 턴을
  통째로 계산해서 결과만 주는 구조라, 중간값을 보여주려면 Core를 바꿔야 해서 비용 대비 효과가 낮다고 판단.
- **다음에 할 일(사람)**: Unity Pull → Play → 전투에서 공격/스킬 한 번 눌러서 로그가 한 줄씩 올라오고
  화면이 짧게 색으로 번쩍이는지, 그 동안 버튼이 잠기는지 확인. 에러 있으면 그대로 붙여넣기.

## 4단계 결과 (필드 탑뷰) — ✅ 실기에서 확인됨
Unity 없이 작업했지만 Unity 참조 DLL(NuGet `UnityEngine.Modules`/`Unity3D.UnityEngine.UI`)로 `Assets/Scripts` 전체 컴파일은 통과(경고 0).
- `Game/Field/FieldLayout.cs`: 칸 좌표만 담당. 한 스테이지 = 아래→위 5줄(0 출발 → 1~3 갈림길: **왼쪽 몹 / 오른쪽 이벤트** → 4 보스),
  줄 사이는 사다리 모양 길. BFS 경로 탐색. **다음 줄보다 위로는 못 걸어감**(노드 건너뛰기 방지).
- `Game/Field/TerrainTiles.cs`: 이미지 파일 없이 16×16 픽셀 타일을 코드로 그림(Point 필터). 지형 4종:
  들판(풀·나무·꽃), 늪(판자길·웅덩이·갈대), 설산(눈·전나무·바위), 사막(모래·선인장·뼈). 아트 교체 시 이 클래스만 바꾸면 됨.
- `Game/Field/FieldView.cs`: 월드 공간 Tilemap(바닥/장식 2층) + 노드 원형 마커 + 파티 말. `Phase == Map`일 때만 보이고,
  스테이지가 바뀔 때만 타일을 새로 깐다(uGUI처럼 매번 다시 그리지 않음). 조작: **방향키/WASD** 한 칸씩, **노드 클릭** 시 자동 이동,
  다음 줄의 열린 노드(맥동 표시)에 도착하면 `GameManager.EnterNode`. 진입 가능 여부는 Core `NodeOptions()`만 판단.
  장식 배치는 별도 시드 → 게임 난수(`run.Rng`)에 영향 없음.
- `MapScreen`: 화면 가운데를 비우고 상단 HUD(스테이지·재화·파티)/하단 HUD(안내·노드 버튼·원석 제작)로 분리.
  하단 노드 버튼도 누르면 말이 걸어간 뒤 진입(걷는 중 중복 입력 무시).
- 카메라: `Main.unity`의 기본 카메라가 원근+스카이박스라 `FieldView`가 **직교·단색 배경으로 강제**. 그래서 다른 화면 배경도
  스카이박스 대신 `Theme.Background` 단색이 된다(의도된 변경).
- **다음에 할 일(사람)**: Unity Pull → Play → 1스테이지 맵에서 ① 지형 타일이 보이는지 ② 방향키로 길만 따라 걷는지
  ③ 몹/`?`/보스 노드 도착 시 전투·이벤트로 넘어가는지 ④ 전투 후 맵으로 돌아오면 말이 그 노드 위에 있는지 ⑤ 스테이지마다 지형이 바뀌는지.
  글자가 안 보이거나 흐리면 `FieldView.NewText`의 `fontSize`/`characterSize` 조정. 에러는 그대로 붙여넣기.

## 5단계 결과 (적 AI · 이벤트 · 원석 시너지) — ✅ 실기에서 확인됨
CoreSim 규칙 테스트 21개 + 봇 2000판 통과, Unity 참조 DLL로 `Assets/Scripts` 전체 컴파일 통과.
- **원석 = 시너지 스킬 해금 (§20-8 팀 확정안)** — `Core/Data/Synergies.cs`(이름·설명·적응 판정), 효과 계산은 `Battle`.
  식성별 원석 1개 = 런 동안 패시브로 켜짐, **중첩 없음 → 이미 가진 원석은 다시 못 만듦**(조각 낭비 방지). 수치는 `Balance`의 제안값.
  - 포식의 원석 → **무리사냥**: 전투 중인 육식 1마리당 아군 전체 공격 +8%
  - 생명의 원석 → **생명의 순환**: 초식이 정화에 성공할 때마다 아군 전체 배고픔 +4
  - 적응의 원석 → **적응**: 잡식이 있을 때만. 초식+잡식 = 정화 +10%p / 육식+잡식 = 공격 +12% / 셋 다 = 공격 +6%·정화 +5%p /
    **잡식뿐**(파티가 줄어드는 3스테이지 대비) = 팀의 두 번째 아이디어 채택: 적 HP 50% 이상이면 공격 +12%, 미만이면 정화 +8%p
- **적 AI**: 적도 종별 스킬 사용(배고픔이 없어서 확률 30%, 보스 45%). 유지형(등딱지·악바리·가시)은 HP 60% 미만에서 켬.
  적에게 의미 없는 스킬은 바꿈: 달래기 = 다친 적 1명 회복, 원숭이 모방 = **파티가 마지막으로 쓴 스킬**을 흉내, 사자 광폭 = HP 50% 미만에서 공격 ×1.3.
  표범 매복은 "노리는 중!"으로 **예고**되므로 방어로 대응 가능. 보스 강타(30%)는 유지.
- **이벤트 2 → 7종** (§20-9 제안안): 연구소 순찰대 / 까마귀 상인(음식·조각 교환) / 오염된 샘 / 굶주린 새끼 여우(스테이지 정화 버프) / 오래된 사냥터(스테이지 공격 버프). 모두 득실이 같이 있는 딜레마형.
- UI: 맵 하단 원석 버튼에 해금될 시너지 이름·효과 표시, 상단/전투 화면에 현재 시너지 한 줄 요약(적응은 현재 구성 기준), 적 상태 태그(노리는 중!/등딱지/회피/독/방어↓), 아군 독 표시.
- **의도적으로 안 한 것**: 칭호·업적(§15), 조합 필살기 버튼(팀 안이 패시브라 불필요).
- 봇 승률 4.8% → 3.9%(적 스킬 추가 영향, 봇은 시너지를 고려하지 않음) → 6단계에서 조정.
- **이벤트 검증 도구**: CoreSim이 7종 이벤트의 모든 선택지를 강제로 실행해 검사(`EventTests`). 에디터/개발 빌드에서는 맵 오른쪽에
  **[테스트] 이벤트 고르기** 패널(`Debug.isDebugBuild`일 때만): 이벤트를 고르면 다음 `?` 노드에서 그 이벤트가 열림, "이벤트 무제한"을 켜면
  스테이지당 1회 제한이 풀려 연달아 확인 가능(`RunState.ForcedEventIndex`/`DebugUnlimitedEvents`, 7단계 데모 모드에서 재활용).
  이벤트 결과 문구가 화면에 안 나오던 문제도 수정(맵 하단에 "이벤트 결과: …" 표시).
  → ✅ 실기 확인: 테스트 패널 표시, 예약한 이벤트 진입, 결과 문구 표시 모두 동작.
- **다음에 할 일(사람)**: Unity Pull → Play → ① 맵에서 원석 버튼 문구·시너지 한 줄이 보이는지 ② 전투 로그에 적 스킬(돌진/독 물기/매복 예고 등)이 뜨는지
  ③ 이벤트 선택지 4개짜리(까마귀 상인)가 화면에 다 들어가는지. 에러는 그대로 붙여넣기.

## 6단계 결과 (밸런스) — ✅ 완료
- **봇 3종** (`Tests/CoreSim/Bots.cs`): 사냥 성향(웬만하면 물리침) / 정화 성향(깎아 두고 정화) / 무작위(하한선).
  "일반 플레이어" 봇은 매복 예고에 방어, 약한 적 집중, HP 낮으면 휴식, 배고픔 70까지만 먹이기, 가장 약한 동물과 작별 등 기본적인 판단을 한다.
  리포트: 승률, 패배 스테이지, 스테이지별 보스 패배율, 보스 입장 시 배고픔/HP, 정화 비율, 전투 길이, 종별 승률.
- **목표**: 사냥 성향 ≈ 정화 성향(§0 "무조건 정답 없음"), 한 판 15~20분. 난이도는 봇보다 **사람 체감** 우선 —
  1차(봇 ~32%) 실기 플레이 결과 "쉽다" → 2차에서 보스 강화(봇 ~21%). 사람이 봇보다 확실히 잘하므로 봇 승률은 낮아도 된다.
